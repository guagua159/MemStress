# MemStress — Windows 内存压力测试工具

用 .NET 10 + WPF 实现的内存压力测试工具，带图形界面与结构化报错日志。

**当前版本 1.9**，零 NuGet 依赖，MIT 许可。

## 它做什么

用 7 种故障模型反复读写你指定比例的内存，把写进去的数据读回来逐字节比对。
任何一位不一致都会记录到日志，附带块号、块内偏移、绝对地址、期望值与实际值。

可选的外部工具交叉验证补足纯内存校验覆盖不到的部分；WHEA 监控把硬件层已纠正的错误也纳入判定。

**报告区分「通过 / 失败 / 未测」三态**：读不到 WHEA 事件日志时写「未监控」而不是「无事件」，
交叉验证未完成时写「无法判定」而不是「通过」。

## 安装

### 方式一：下载发行版（推荐）

从 [Releases](https://github.com/guagua159/MemStress/releases) 下载 `MemStress-1.9-win-x64.zip`，
解压到任意目录，双击 `MemStress.exe` 即可运行。不需要安装 .NET SDK，也不需要编译。

**运行前必须安装 .NET 10 桌面运行时**（.NET Desktop Runtime 10.0）。

未安装时双击会提示 `You must install .NET to run this application.`

下载地址（微软官方）：https://dotnet.microsoft.com/en-us/download/dotnet/10.0

在该页面「Run desktop apps」一节下载 **.NET Desktop Runtime** 的 x64 安装包并安装。

注意两点：

- 只装「.NET Runtime」不够，那是给控制台程序用的。本程序是图形界面程序，需要 **Desktop Runtime**。
- 版本必须是 **10.x**。装 8.x 或 9.x 都不能运行本程序。

确认是否已安装，打开命令提示符执行：

```
dotnet --list-runtimes
```

输出中应包含 `Microsoft.WindowsDesktop.App 10.x.x` 这一行。

### 方式二：从源码构建

需要 .NET SDK **10.x**（10.0.100 或更高版本）。

```bash
dotnet build src/MemStress/MemStress.csproj
```

构建产物落在仓库根目录，双击 `MemStress.exe` 即可运行。此方式不需要单独安装桌面运行时——
SDK 已包含运行时。

### 开启大页（可选，需管理员）

无论用哪种方式安装，都建议以管理员身份运行，这样才能使用大页（2 MB），覆盖率更高。
非管理员运行会自动回退到 4 KB 页，界面与报告都会标注实际使用的分配方式。

```
secpol.msc → 本地策略 → 用户权限分配 → 锁定页面 → 添加当前用户 → 重新登录
```

## 使用

### 基本流程

1. 选择档位（默认「标准」）
2. 调整内存占用百分比（默认 85% 可用内存）
3. 点「开始测试」

测试期间界面实时显示时长、吞吐、累计读写量、轮次与错误数。发现的错误列在下方的错误表格里。

### 档位选择

| 档位 | 模式数 | 说明 |
|---|---|---|
| 快速筛查 | 2 | 耗时最短，用于初步确认 |
| 标准 | 4 | 默认档位，日常使用 |
| 深度 | 6 | 覆盖更多故障类型 |
| 彻底 | 7 | 最全面，耗时明显更长 |

### 界面页签

| 页签 | 内容 |
|---|---|
| 压测 | 参数设置、实时指标、错误表格 |
| 报告 | 查看报告、打开日志目录 |
| 运行日志 | 运行过程逐行日志 |
| y-cruncher | 外部工具发现与运行 |
| 方法与局限 | 判读规则、已知局限、参考来源 |

### 测试模式

7 种模式，每种针对一类内存故障。档位会自动选择其中若干种。

| 模式 | 说明 |
|---|---|
| MovingInversion | 写 A → 写 ~A → 读回，搬运整块数据 |
| AddressAsData | 把块内偏移写进内存再校验，检查地址译码 |
| RandomFill | 随机字节流写入后整块比对，覆盖面最广 |
| BlockCopy | 相邻块互为源和目的拷贝后校验 |
| WalkingOnes | 单比特在字节内依次置位，边走边校验 |
| Checkerboard | 交替 0x55/0xAA 填充 |
| ModuloX | 按模数打散访问顺序，检查被缓存掩盖的错误 |

## 输出

每次测试在 `logs\<时间戳>-<模式>\` 下生成：

| 文件 | 内容 |
|---|---|
| `session.json` | 机器信息、NUMA、大页粒度、参数、版本 |
| `errors.csv` | 每条错误一行，可直接用 Excel 打开 |
| `errors.jsonl` | 同上，JSON Lines 格式 |
| `report.md` | 导出报告：结论、机器信息、错误明细、判读依据 |

## 外部工具（可选）

程序不下载任何第三方二进制。需要时请自行获取，放进 `tools\<id>\` 目录。

| 工具 | 用途 | 官方地址 |
|---|---|---|
| y-cruncher | 非缓存负载，补充内存控制器与缓存层次的验证 | https://www.numberworld.org/y-cruncher/ |

程序会按以下顺序查找：手动指定的路径 → `tools\<id>\` → 机器上常见安装位置
（`C:\Tools`、`C:\Program Files`、`C:\y-cruncher`）。已装在别处的工具不需要移动。

### y-cruncher 档位

| 档位 | 算法 | 每项时长 | 总时限 | 内存 |
|---|---|---|---|---|
| 快速筛查 | N63 + VT3 | 60 s | 15 分钟 | 物理内存 70% |
| 标准验证 | FFTv4 + N63 + VT3 | 120 s | 1 小时 | 物理内存 85% |
| 深度驻留 | FFTv4 + N63 + VT3 | 300 s | 4 小时 | 物理内存 90% |

在 y-cruncher 页选择档位后点「运行」即可，参数会按物理内存自动计算。

停止时只清理本次启动的进程，你在程序外自己开的 y-cruncher 不会被误杀。

## 判读结果

- **出现任一内存错误** → 不通过。错误集中在同一块、同一偏移时，优先怀疑该地址区间或时序参数。
- **内存零错误但出现 WHEA 事件** → 仍判不通过。
- **测试被中止** → 不给结论，只给证据。
- **全部通过** → 表示「本次配置下未发现错误」，不等于内存绝对可靠。

## 已知局限

- 大页不可用时回退 4 KB 页，覆盖率下降，界面与报告都会标注。
- 只能测用户态可分配的物理内存，内核占用与保留区测不到。
- 温度相关的不稳定需要配合 GPU 负载或长时间运行才能复现。
- 不改系统设置、不装驱动、不需要重启。

## 命令行自检

用于验证程序本身功能是否正常，退出码 `0` 通过、`2` 失败：

```bash
# 基本跑通：8 秒，占 20% 可用内存
MemStress.exe --selftest --seconds 8 --percent 0.2

# 报错链路：故意写坏一个字节，验证日志三处都能看到
MemStress.exe --selftest --seconds 8 --percent 0.2 --inject-error

# 外部工具编排链路
MemStress.exe --toolselftest

# WHEA 解析与判定链路
MemStress.exe --wheaselftest

# 工具发现：列出找到的工具与搜索过的目录
MemStress.exe --toolscan

# y-cruncher 日志解析与失败判定
MemStress.exe --yctailtest

# CSV 转义与日志写失败降级
MemStress.exe --p0test
```

`--selftest` 的内存占用默认是 0.2，不会去抢 85% 内存。
